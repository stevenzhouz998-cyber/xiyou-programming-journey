# 验证分层与证据复用

目标是减少重复执行，保留真实玩家行为、存档、安全和五项目浏览器验收。分层是选择顺序，不是豁免依赖验证。

| 改动 | 开发中的必要检查 | 扩大验证的条件 |
| --- | --- | --- |
| 纯说明、工作流规则 | 内容、链接、差异检查；工程脚本运行自身回归 | 改到可执行配置或影响产品验收要求时补相关检查 |
| 局部组件/关卡 | 相关 unit、typecheck；行为有变化时运行该关相关真实浏览器路径 | 依赖、边界、可访问性或布局受影响时覆盖相应项目；关卡交付保留完整五项目矩阵 |
| Worker/语法 | 对应语法与 runner 回归、安全/超时/取消/加载/迟到消息，以及真实 Worker 浏览器验证 | 公共运行能力变更时覆盖所有使用关卡，不以 mock 替代真实执行 |
| 存档/schema/context/奖励/家长报告 | 共享存档与上下文回归，迁移、失败恢复、相关新旧关卡及家长浏览器路径 | 无法可靠限定影响范围时执行全站回归；共享证据不可按关卡名缩窄 |
| 发布/商业完成 | 全站测试、构建/预算/素材及全部发布门禁 | 线上验证另需部署授权；已知失败未闭合不得称全站通过 |

## 批处理

一份稳定源码状态的相关 E2E 放在同一条调用中，只触发一次构建。例如第四周：

```sh
npm run verify:record -- npm run test:e2e -- e2e/week-four-blockly-python-mapping.spec.ts e2e/week-four-python-variable-overwrite.spec.ts e2e/week-four-python-branch-structure.spec.ts
```

执行前用 `rg --files e2e` 核实名称；不设置减少项目的 `--project` 来代替五端交付。开发定位单个故障可以定点跑，但证据必须明确限定范围。暂不改变 worker、timeout、retry 或全站命令。

## 工具

```sh
npm run verify:record -- npm run test:workflow
npm run verify:record -- npm run typecheck
npm run verify:reuse -- artifacts/verification/<本次生成目录>/evidence.json
```

`verify:record` 直接执行指定命令，完整输出留在本地 `artifacts/verification/`，终端只给结果、耗时与文件位置。失败时读取日志中的相关段落，不默认把整个日志送入上下文。长命令等待期间仍应保持有意义的用户沟通。

每次记录开始/结束输入指纹、命令、退出码、日志和耗时。指纹覆盖整个 src/e2e/scripts/public、素材说明、CI、根配置与锁文件、已安装依赖锁记录、HEAD、工作区、Node/系统及相关环境标记。未跟踪源码也被覆盖；文档正文和生成报告不触发源码失效。

`verify:reuse` 只检查记录是否成功、文件指纹是否一致、日志是否存在。失败、执行期间输入变化或之后输入变化，都会返回非零状态。它不自动跳过任何测试，也不把命令成功解释为产品完成。

边界：这不是防篡改证明或完整环境封存。手工修改 node_modules、外部服务、浏览器安装版本、浏览器存储/测试夹具、验收要求变化，都需要额外判断或重新验证。未知环境变化一律不复用。源码指纹采用保守全量策略，因此任意源码变化都可能使局部证据失效；先保证不误用，再考虑依赖图优化。

## 失败处理与停止条件

- 新失败先复现、归属本次变更或历史基线；保留命令、版本、日志和用户影响。
- 不能把 31 项历史失败标成现在仍失败，也不能把旧问题当作可忽略项目。
- 修复后只先复跑对应失败路径；必要检查通过且没有新改动/具体风险时停止重复验证。
- 最终审查合并规格符合性与代码质量，聚焦高风险边界；有实际收益才独立委派。禁止机械地为每个组件追加两位审查者。

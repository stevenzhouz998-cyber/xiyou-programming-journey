# 《西游编程记》商业基础层设计规格

## 目标与完成等级

本子项目为后续课程、战斗、成长、装备和神兽系统建立可靠底座，交付版本化存档与恢复、儿童隐私、响应式布局、无障碍设置、性能预算和真实浏览器验收。

目标完成等级为相关 `Parent / saves` 与 `UI / release` 行的 **System loop complete**。本子项目完成不代表整站达到 **Commercial production complete**。

## 当前基线与已知缺口

- 当前进度格式只有 `ProgressV1`，损坏数据会被静默丢弃并重置。
- 导入只验证版本和少数字段，非法关卡、星数、时间和设置可能进入运行态。
- 没有写入前快照、损坏源保留、迁移注册表或恢复状态提示。
- 页面设置 `min-width: 1180px`，手机和平板无法正常使用。
- `lang="en"` 与简体中文内容不一致。
- Phaser 产物约 1.48 MB，虽动态导入，但缺少首页、任务页和交互性能预算。
- 现有测试只覆盖第一关主路径与少量导入异常，缺少真实浏览器、恢复、键盘和多视口证据。

## 支持范围与量化预算

### 设备、浏览器和输入

- 关键视口：手机 `390 × 844`、平板 `768 × 1024`、桌面 `1440 × 1024`。
- 浏览器：当前稳定版及前一个稳定版的 Chromium、WebKit/Safari 和 Firefox。
- 输入方式：触摸、鼠标、键盘。
- 页面主路径在 `320px` CSS 宽度下不得产生整页横向滚动；Blockly 和代码编辑器可以在自身受控区域内滚动。

### 性能预算

- 首页首载 JavaScript gzip 总量不超过 `180 KB`，Phaser 与任务编辑器不得进入首页首载关键路径。
- 首页首载静态资源传输总量不超过 `650 KB`；正式资产引入后仍需保持该预算或在变更规格中明确批准新预算。
- Lighthouse 移动模拟下：LCP `≤ 2.5s`、CLS `≤ 0.1`、INP `≤ 200ms`。
- 从进入任务页到场景与当前编辑器可操作 `≤ 3s`；加载失败时 `1s` 内显示可恢复的文字状态。
- 构建不得出现未解释的大包警告；已批准的懒加载 Phaser 包必须在性能报告中单独列出。

## 架构边界

### 版本化存档域

将进度数据升级为 `ProgressV2`，并把解析、迁移、验证、存储事务和 React 状态分离：

1. **Schema 与验证**：纯函数验证完整数据结构、范围、枚举、已知关卡 ID 和 ISO 时间。
2. **迁移注册表**：按版本逐级迁移；首个迁移为 V1 → V2。未知未来版本拒绝载入，不覆盖现有数据。
3. **存储事务**：使用三个本地键保存当前数据、上一份已验证快照和最近一次损坏原文。写入顺序为“验证新数据 → 当前值复制为快照 → 写入新当前值”。
4. **恢复结果**：载入返回数据和明确状态，不用异常或静默重置隐去恢复事件。
5. **React 上下文**：只消费存储域的结果，负责向页面展示恢复通知和家长操作，不自行解析 JSON。

`ProgressV2` 在保留 V1 关卡与设置的基础上新增：

- `version: 2`。
- `schemaRevision`，用于同一大版本内的兼容修订。
- `privacy`：仅保存是否看过本地数据说明，不保存生日、学校、地址、联系方式或在线标识。
- `recovery`：最近一次成功恢复的时间和来源类型，不保存损坏原文副本本身。

后续成长、装备和神兽字段不在本子项目中提前伪造；它们应由各自规格通过 V2 的后续 schema revision 或新版本加入。

### 响应式应用壳

- 去除全局最小宽度。
- 桌面端保留现有双栏视觉方向；平板采用收窄双栏或单栏；手机按“任务目标 → 场景 → 编辑器 → 反馈 → 故事与提示”排列。
- 顶部导航在窄屏收敛为可访问的紧凑操作区，不隐藏静音、成长地图或家长入口。
- 任务编辑器保持真实 Blockly、CodeMirror 和 AI 交互，不以静态替代界面换取适配。
- 成功弹窗、家长 PIN、导入与恢复通知必须适配手机并管理焦点。

### 隐私与设置

- `html lang` 改为 `zh-CN`。
- 首页和家长页明确说明数据只保存在当前浏览器；不发送分析、广告或儿童行为数据。
- 提供可阅读的本地数据说明：保存内容、用途、导出、清空和恢复机制。
- 静音和减弱动画均由可见控件控制并持久化；首次载入同时尊重系统 `prefers-reduced-motion`，用户明确选择优先。
- 清空进度只允许在家长验证后进行，要求二次确认，并在清空前生成可下载备份。

## 数据流与失败行为

### 正常载入

1. 读取当前键。
2. 解析、逐版本迁移并严格验证。
3. 返回 V2 数据和 `normal` 状态。
4. React 渲染，不显示恢复警报。

### 当前存档损坏

1. 将无法解析或无法验证的当前原文复制到损坏源键。
2. 验证上一份快照。
3. 快照有效时恢复为当前值，返回 `recovered-from-snapshot`，显示非阻塞通知，并允许家长下载损坏原文。
4. 快照也无效时创建初始 V2，但同时保留两份损坏原文，返回 `reset-after-corruption`，明确告知家长发生了什么。

### 导入

- 导入先在内存中解析、迁移和验证，通过后才替换当前存档。
- 失败不得修改当前、快照或 React 状态。
- 成功导入前把原当前存档写入快照，页面显示来源版本和导入结果。

### 存储写入失败

- `QuotaExceededError` 或禁用存储不得让刚完成的关卡显示为已安全保存。
- 页面保留当前会话中的结果，显示“本次进度尚未保存”，提供重试和导出。
- 后续功能不得吞掉写入异常。

## 产品可见行为

- 孩子正常使用时不被技术错误打断。
- 发生自动恢复时，孩子看到简短温和提示；详细数据与下载入口只在家长页出现。
- 家长页新增数据状态、最后保存时间、导出、严格导入、清空和恢复信息。
- 任何恢复、导入或清空操作都给出明确成功或失败结果。
- 错误不扣星、不锁关、不删除仍可恢复的数据。

## 测试与验收

### 单元与集成

- V1 → V2 迁移保留关卡、星数、提示、设置和时间。
- V2 完整字段、范围、关卡 ID、时间和枚举验证。
- 当前值损坏、快照有效；两者都损坏；未知版本；部分字段缺失。
- 导入失败不改变任何现有状态；导入成功生成快照。
- 写入失败返回可观察状态并支持重试与导出。
- 清空操作在确认前不改变数据，确认时先生成备份。
- 静音、减弱动画和隐私说明状态刷新后保持。

### 真实浏览器路径

- 桌面：首次进入 → 第一关失败 → 正确完成 → 刷新恢复 → 家长导出 → 合法导入。
- 恢复：注入损坏当前值 → 刷新 → 自动恢复快照 → 家长下载损坏原文。
- 导入失败：选择畸形文件 → 显示具体错误 → 原进度保持不变。
- 手机：完成首页、第一关、提示、失败、成功和返回地图，不出现整页横向滚动。
- 键盘：完成导航、家长 PIN、导入触发、恢复通知和弹窗关闭；焦点不丢失或落入背景。
- 减弱动画与静音：系统偏好和用户设置都产生可观察效果。

### 发布前命令与证据

- `npm test`
- `npm run typecheck`
- `npm run build`
- 多浏览器真实操作记录与关键视口截图。
- 构建体积报告和性能预算对比。
- 控制台错误、404、资源路径和 GitHub Pages 基础路径检查。

## 非目标

- 本子项目不实现神兽、伙伴、奖励、装备、法宝或战斗玩法。
- 不重写 30 关内容，也不把第一关证据外推到全部关卡。
- 不生成新的正式插画；若现有资产继续发布，后续资产子项目必须补齐来源清单和视觉 QA。
- 不引入账号、云同步、分析 SDK、广告、支付或外部儿童数据服务。

## 剩余风险与后续依赖

- 本地浏览器存储仍可能被用户主动清除；导出备份和明确说明只能降低风险，不能提供云端恢复。
- Blockly、CodeMirror 和 Phaser 在低端移动设备上的真实性能必须以实施后的浏览器测量为准。
- 完成本子项目后，整站仍缺真实战斗、成长经济、神兽伙伴、30 关全量浏览器证据和正式资产来源清单，因此仍为 `not complete`。

# `xiyou-karpathy` 项目 Skill 设计规格

## 目标

为《西游编程记》建立项目级工程门禁，防止把页面、配置、静态演示或局部测试误报为完整产品。后续涉及课程、成长、神兽、法宝、伙伴、战斗、存档、家长功能、UI、视觉资产与发布的任务都必须使用此 Skill。最终目标是完整商业级网站，而不是原型、薄 MVP 或阶段性交差产物。

## 位置与触发

- Skill 路径：`.agents/skills/xiyou-karpathy/SKILL.md`
- 项目入口：在 `AGENTS.md` 中声明上述任务必须先读取并执行该 Skill。
- Skill 名称：`xiyou-karpathy`

## 核心门禁

1. **先定义真实行为**：实现前列出玩家输入、系统状态变化、跨系统影响和可观察结果。
2. **拒绝空壳**：仅有 UI、配置、文案、动画或硬编码成功路径，不得称为功能完成。
3. **闭环优先**：奖励必须能消费或产生后续作用；养成必须改变选择或玩法；战斗必须由代码真实驱动。
4. **逐层标记完成度**：只允许使用“设计完成、配置完成、原型可演示、单关可玩、系统闭环、全量验收、生产完成”等明确等级。
5. **测试先行**：功能或修复先写失败测试；测试必须覆盖正确路径、失败路径、刷新恢复、损坏数据和边界条件。
6. **真实浏览器验证**：涉及交互的功能必须从公开或本地页面完成真实操作，不以 DOM 存在或单元测试代替完整行为。
7. **全量声明需全量证据**：宣称 30 关完成必须逐关结构校验、模式校验和至少一条自动化通关路径；不能由第一关推断其余关卡。
8. **儿童体验保护**：失败不惩罚；辅助不能代答；养成不能制造掉级、离开、付费抽取或限时焦虑。
9. **原著与游戏层分离**：新增神兽、营地和战斗表现必须明确属于现代学习游戏层，不改写原著事件、人物关系和结局。
10. **完成声明审计**：交付前输出证据、未覆盖项和剩余风险；任何必要验收未执行时禁止使用“全部完成”。
11. **商业级交付**：完成证据必须覆盖真实行为、状态持久化、失败恢复、跨系统作用、性能、响应式、键盘与减弱动画、儿童隐私、部署和长期维护。
12. **正式资产只用内置视觉工具**：角色、神兽、场景、装备、法宝、特效、收藏图和装饰图必须由环境内置图像生成或编辑工具完成，或来自已批准且来源可验证的项目资产。
13. **禁止代码绘图冒充美术**：Flutter、SwiftUI、CSS art、div art、emoji、ASCII、占位框、手写 SVG、代码生成画布和近似图形不得作为正式美术资产。可靠图标库只用于界面图标。
14. **资产可追溯**：每个正式资产必须记录用途、生成工具、提示词或来源、尺寸、授权/来源状态和使用位置；发布前不存在未替换占位资产。

## 工作流

1. 读取任务与现有代码，列出假设和缺口。
2. 定义可验证成功标准及完成等级。
3. 先写会失败的测试或验收脚本。
4. 做最小但完整的系统实现，避免无关重构。
5. 运行单元、集成、构建与浏览器行为验证。
6. 对照项目门禁审计跨系统闭环。
7. 按证据报告完成等级和未完成项。

## Skill 内容

- `SKILL.md`：核心工作流、完成等级、证据矩阵和禁止事项。
- `references/completion-matrix.md`：项目系统的最低完成证据，包括课程、Blockly、Python、AI、成长、神兽、法宝、战斗、存档、家长与 UI。
- `references/asset-provenance.md`：正式视觉资产的来源、工具、生成提示、尺寸、授权状态和使用位置模板。
- `agents/openai.yaml`：项目 Skill 的显示名称、简介和默认提示。
- 不创建脚本；当前门禁主要依赖项目测试与浏览器验证，不需要重复包装已有命令。

## 验收

- Skill 通过官方 `quick_validate.py`。
- `agents/openai.yaml` 与 `SKILL.md` 内容一致。
- `AGENTS.md` 明确要求后续产品和工程任务使用该 Skill。
- 使用一个“新增神兽技能”的示例任务做静态走查，能够识别 UI 空壳、自动代答、缺少存档和缺少跨关作用。
- 使用一个“新增神兽正式立绘”的示例任务做静态走查，能够拒绝 emoji、CSS art、Flutter、SwiftUI、手写 SVG 和占位图，并要求内置工具资产与来源记录。
- 商业级完成矩阵包含性能、可访问性、儿童隐私、保存恢复、资产来源、全量关卡、公开部署和剩余风险。
- 提交只包含 Skill、引用文件、项目入口和本规格，不混入产品功能修改。

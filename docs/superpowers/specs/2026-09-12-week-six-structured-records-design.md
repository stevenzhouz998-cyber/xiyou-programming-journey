## 推荐方向及替代

推荐“字典记录 + 列表循环 + 按字段生成表格”。沿用已学列表与循环，只增加有名称的字段及取值，让数据结构直接影响可见结果。固定引用与字典示例帮助理解标点，不把打字速度当成学习目标。

替代一：纯拖拽事实表，操作轻，但削弱本关 Python 衔接。替代二：自由从故事写完整数据集，开放性强，但同时增加阅读、数据建模和语法负担。推荐先用提供好的记录练习取值，后续课程再增加自主建模。

## 玩家操作与可见结果

目标：理解一条记录把“第几调”和“经过”放在一起；同一个字段名可从每条记录取出相应信息。页面保留现有明亮故事书方向；这不是新的视觉方案。

上方是三张始终可查的事实卡，标明来源回目和教学摘要。中间是可见 Python 编辑器，下方是本次真实运行产生的两列表格。事实卡是公开材料，运行表格是孩子程序的实际输出，两者有明确标签。

默认代码（所有代码均可见）：

```python
records = [
    {"第几调": "一调", "经过": "得到假扇，火势更旺"},
    {"第几调": "二调", "经过": "取得真扇，随后被骗回"},
    {"第几调": "三调", "经过": "最终借得真扇，灭火通行"},
]

for record in records:
    record_attempt(record["第几调"], record["第几调"])
```

教学 API `record_attempt` 只向学习记录表写入一行，不操作角色战斗或原著事件。页面公开说明它的第一个参数填“第几调”，第二个参数填“经过”；提供一个无关借扇答案的字典取值示例。

默认程序合法且真实执行，输出三行，但“经过”列也显示一调、二调、三调。只报告首个语义阻塞，例如“第一行的经过栏重复了调次，还没有记录发生的事情”，定位实际取值表达式，不直接给出修正代码。孩子把第二次取值改为 `record["经过"]` 后完整重跑，表格才显示三次各自的经过。

默认只有这一处取值错误，不叠加原著纠错、排序和新函数定义题。重复运行和失败零惩罚；提示不改码、不运行、不补答案。既有装备辅助只沿用已经批准且适用的能力。

# W5-M5 车迟国故事总编排：综合复用第五周 Python 能力

状态：2026-09-11 用户明确批准“一个总函数串起第五周四类已学能力”的方向，并授权代理决定本地实现与验证细节。本关目标证据等级是本地 **One-level playable**；不把单关通过扩大为第五周 `System loop complete`、30 关 `Full-content verified`、公开部署或商业完成。

## 玩家输入与完整运行

孩子只编辑一个可见 CodeMirror 程序，并用一次“运行完整故事”从头执行。程序由九个函数组成：

- `rescue_monks()` 用 `for monk in monks` 为甲、乙、丙逐人解困并登记；
- `record_sanqing()` 记录到达和留下名字；
- `weather(order)` 记录收到的风、云、雷、雨参数；
- `record_weather_sequence()` 依次调用四次 `weather(...)`；
- `record_meditation()`、`record_guess()`、`record_final_trials()` 分别记录后续比试；
- `record_later_trials()` 按故事顺序调用三个小函数；
- `record_chechi_story()` 是唯一总编排，按解困、三清观、天气、后续比试的顺序启动四个阶段；顶层只调用它一次。

九个函数的定义顺序允许调整，只要 Python 在顶层启动前已经完成全部定义。函数体和运行调用关系决定成功，不能要求孩子背诵某个定义排列。

## 四个顺序阻塞点

默认源码同时含有四个真实错误，一次完整运行只诊断排在最前的阻塞点；完整真实执行记录仍可查看：

1. `register(monk)` 在循环外，只登记最后一名僧人；
2. 总编排漏掉 `record_sanqing()`；
3. `weather(order)` 忽略参数，固定记录“风”；
4. `record_later_trials()` 先调用猜物再调用坐禅，后续小函数顺序错误。

孩子每修复一个错误都必须重新运行整份程序；成功前缀不得缓存或跳过。四个错误及结构错误、Worker 加载或执行故障均为零惩罚，不损失生命、资源或星星。失败观察和分层提示只能引用当前已保存的真实失败快照，不能改写、重排、运行或补全代码，也不能直接给出答案。

## 受限语法与真实执行

程序最多 64 行、2400 字。只允许上述九个函数、`monks` 列表、`for monk in monks`、已经学过的直接函数调用、四个天气字符串和五个后续故事记录字符串。禁止 `return`、条件、`while`、推导式、递归、导入、属性访问、文件、网络和任意内建能力。

可见源码先原子保存，再发送给同源独立 Pyodide Worker。Worker 通过 AST 白名单检查并实际执行，记录函数定义、根/阶段/小函数调用者与层级、循环迭代和目标、参数绑定、动作所属函数与源码行。主线程从同一保存源码独立推导规范轨迹，并逐字段核对 Worker 轨迹和运行结果。stdout、输出文本、隐藏答案、预期序列、React 状态、坐标、动画或测试注入都不能决定完成。
